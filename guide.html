0. 빠른 시작 (5분)

아래 순서대로 하면 바로 쓸 수 있습니다. 단계마다 자세한 설명으로 가는 링크가 있습니다. 토큰 만들기는 PC에서 하는 것이 편합니다. 토큰·저장소·이슈 같은 말이 낯설면 1장의 처음 듣는 말 정리를 먼저 보세요.

먼저 확인하세요: 이 홈페이지는 할 일 저장소 주인 계정(LEEYONGJAE-1)으로만 설정할 수 있습니다. 다른 GitHub 계정으로는 이 저장소용 토큰을 만들 수 없습니다. 다른 사람이 쓰려면 먼저 13장을 보세요.

  1. 토큰 만들기 (약 3분)
    LEEYONGJAE-1 계정으로 GitHub에 로그인한 뒤 토큰 발급 페이지를 엽니다. 홈페이지 ⚙ 설정의 토큰 발급 페이지 열기를 눌러도 같은 곳으로 갑니다. 이름을 적고, 만료(Expiration)는 90 days, Repository access는 Only select repositories → my-todo, 권한은 Issues: Read and write로 고릅니다. Generate token을 누르고, 나온 토큰을 복사합니다. → 자세히: 2-1
  2. 홈페이지에 넣기
    홈페이지의 GitHub 토큰 칸에 붙여 넣고 저장을 누릅니다. → 자세히: 2-2
  3. 연결 확인
    저장하면 연결을 저절로 확인합니다. 설정 칸이 닫히고 「GitHub 연결에 성공했습니다. 할 일 목록을 불러옵니다.」라는 메시지가 나오면 성공입니다. 나중에 다시 확인하려면 ⚙ 설정 → 연결 테스트를 누릅니다. → 자세히: 2-2, 실패하면 14장
  4. 첫 할 일 등록
    입력 칸에 오늘까지 보고서 작성하기를 적고 입력을 누릅니다. 「등록했습니다: #21 보고서 작성」라는 메시지가 나오고, 🟠 긴급 그룹에 "보고서 작성"이 보입니다. 번호는 저장소마다 다릅니다. → 자세히: 5장
    우선순위나 마감이 생각과 다르게 들어갔으면 그 줄의 ✏ 변경을 눌러 고르고 저장을 누릅니다. → 자세히: 6-6
  5. 완료
    그 줄의 완료를 누르거나, 입력 칸에 보고서 작성 완료라고 적습니다. 「완료했습니다: #21 보고서 작성」라는 메시지와 되돌리기 (5초)가 나옵니다. → 자세히: 7장
  6. 휴대폰에 설치
    휴대폰 브라우저로 홈페이지 주소를 엽니다. 안드로이드 크롬은 ⋮ → 앱 설치, 아이폰 사파리는 공유 버튼(□↑) → 홈 화면에 추가를 누릅니다. 토큰은 기기마다 따로 저장되므로 휴대폰에서도 한 번 넣습니다. 휴대폰 브라우저에서 홈페이지 ⚙ 설정 → 토큰 발급 페이지 열기를 눌러 2-1과 같은 설정으로 휴대폰용 토큰을 새로 만들고, 그 자리에서 복사해 붙여 넣습니다. → 자세히: 3장, 2-4

1. 이 앱은 무엇인가요

What's Next는 할 일을 적고, 급한 순서로 묶어 보여 주고, 끝난 일을 정리해 주는 홈페이지입니다. 휴대폰과 PC 어디서 열어도 같은 목록이 보입니다.

  • 주소: https://leeyongjae-1.github.io/my-todo-page/
  • 할 일이 저장되는 곳: GitHub(깃허브)의 비공개 저장소 LEEYONGJAE-1/my-todo입니다. 할 일 1개가 이슈(Issue) 1개이고, 완료하면 그 이슈를 닫습니다(Close).
  • 홈페이지는 그 이슈를 읽고 쓰는 "창"입니다. 브라우저 기록을 지우거나 기기를 바꿔도 할 일은 GitHub에 그대로 있습니다.

처음 듣는 말 정리

GitHub
원래 개발자가 코드를 보관하는 인터넷 서비스입니다. 여기서는 할 일 보관함으로 씁니다.
저장소(repository)
GitHub 안의 폴더 같은 공간입니다. 할 일 저장소 이름은 my-todo이고, 비공개라 주인만 볼 수 있습니다.
이슈(Issue)
저장소에 남기는 글 한 건입니다. 제목·본문·댓글·라벨이 있습니다. 이 앱에서는 할 일 1건입니다.
라벨(label)
이슈에 붙이는 꼬리표입니다. 우선순위(p1·p2·p3), 영역(area:work 업무·area:personal 개인), 대기(waiting), 프로젝트(proj:코드) 등을 라벨로 표시합니다.
토큰(token)
이 홈페이지가 내 할 일 저장소를 읽고 쓸 수 있게 허락하는 열쇠 문자열입니다(github_pat_로 시작). 비밀번호처럼 다룹니다.

토큰은 어디에 저장되나요?

  • 토큰은 지금 쓰는 그 브라우저 안(localStorage)에만 저장됩니다. 다른 기기·다른 브라우저와 공유되지 않습니다.
  • 홈페이지는 토큰을 GitHub API 주소(api.github.com) 말고는 어디에도 보내지 않습니다. 다른 주소로 가는 요청은 코드에서 막습니다. 외부 스크립트도 쓰지 않습니다.
  • 단, 🆘 막막해요를 쓰면 GitHub에서 실행되는 Claude(AI)가 그 할 일을 읽습니다. 이때 할 일 내용이 Anthropic(Claude를 만든 회사)으로 전송됩니다.

PC나 Claude 앱의 Claude Code(/todo-add 같은 명령)로도 같은 할 일을 다룰 수 있습니다. 이 설명서는 홈페이지 사용법만 다룹니다.

2. 처음 설정 (단계별)

처음 한 번 GitHub에서 토큰을 만들어 홈페이지에 넣으면 됩니다. PC에서 하는 것이 편하고, 10분쯤 걸립니다.

2-1. GitHub에서 토큰 만들기

  1. PC 브라우저로 github.com에 로그인합니다. 할 일 저장소의 주인 계정(LEEYONGJAE-1)으로 로그인해야 합니다. GitHub 안내에 따르면 이메일 인증을 마친 계정이어야 토큰을 만들 수 있습니다.
  2. 오른쪽 위 프로필 사진을 누르고 Settings를 누릅니다.
  3. 왼쪽 메뉴(맨 아래쪽)의 Developer settings를 누릅니다.
  4. Personal access tokens 아래의 Fine-grained tokens를 누릅니다.
  5. Generate new token을 누릅니다. 홈페이지 ⚙ 설정의 토큰 발급 페이지 열기를 누르면 이 화면으로 바로 갑니다.
  6. Token name: 알아보기 쉬운 이름을 적습니다. 예: my-todo 홈페이지 PC. 설명(Description)은 비워 둬도 됩니다.
  7. Expiration(만료): 90 days를 권장합니다. 여기서 고른 기간이 지나면 토큰을 쓸 수 없게 되어 새로 만들어야 합니다(2-3).
  8. Resource owner(소유자)가 보이면 내 계정(LEEYONGJAE-1)인지 확인합니다. 토큰은 여기서 고른 소유자의 저장소만 다룰 수 있습니다.
  9. Repository access: Only select repositories를 고르고, 목록에서 my-todo 하나만 선택합니다.
  10. Permissions의 저장소 권한(Repository permissions)에서 Issues를 찾아 Read and write로 바꿉니다. Metadata: Read-only가 함께 선택되면 그대로 둡니다. 다른 권한은 주지 않습니다.
  11. 맨 아래 Generate token을 누릅니다. 확인 창이 나오면 내용을 보고 한 번 더 누릅니다.
  12. 화면에 github_pat_로 시작하는 긴 문자열이 나옵니다. 바로 복사합니다. 보통 이 화면을 벗어나면 토큰 값을 다시 볼 수 없습니다. 복사를 놓쳤으면 그 토큰을 지우고(2-5) 새로 만들면 됩니다.

이 순서는 GitHub 공식 문서 Managing your personal access tokens를 기준으로 정리했습니다. GitHub 화면의 메뉴 이름·위치와 문구는 바뀔 수 있습니다.

주의: Administration이 아니라 Issues입니다

  • Issues 대신 Administration을 골랐던 일이 실제로 있었습니다. 권한 목록에서 꼭 Issues를 찾아 Read and write로 바꾸세요.
  • Administration은 저장소 설정을 바꾸는 강한 권한입니다. 이 앱에는 필요 없고, 이 권한만으로는 할 일을 읽지도 못합니다.
  • 권한을 잘못 고르면 연결 테스트는 성공합니다. 그런데 목록 자리에 「목록을 불러오지 못했습니다: 권한이 없습니다. 토큰에 my-todo 저장소의 Issues 읽기·쓰기(Read and write) 권한이 있는지 확인하세요.」라는 메시지가 나옵니다.
  • 잘못 만든 토큰은 GitHub에서 지우고(2-5) 처음부터 다시 만드세요. 필요한 권한은 Issues: Read and write 하나뿐입니다.

2-2. 홈페이지에 토큰 넣기

  1. 홈페이지를 엽니다. 토큰이 아직 없으면 설정 칸이 처음부터 열려 있습니다. 닫혀 있으면 오른쪽 위 ⚙ 설정을 누릅니다.
  2. GitHub 토큰 칸에 복사한 토큰을 붙여 넣습니다.
  3. 저장을 누릅니다. Enter 키를 눌러도 됩니다.
  4. 저장하면 연결을 저절로 확인합니다. 성공하면 설정 칸이 닫히고 「GitHub 연결에 성공했습니다. 할 일 목록을 불러옵니다.」라는 메시지가 나옵니다.
  5. ⚙ 설정을 다시 열면 맨 위에 「저장된 토큰: 있음 (이 브라우저에만 저장됨)」이 보입니다. 이것으로 설정이 끝납니다.
  • 연결만 다시 확인하려면 ⚙ 설정 → 연결 테스트를 누릅니다. 「연결 성공: LEEYONGJAE-1/my-todo (비공개 저장소)」라는 메시지가 나오면 정상입니다.
  • 「연결 실패: …」라는 메시지가 나오면 뒤에 붙은 이유를 보고 14. 자주 묻는 질문을 확인하세요.
  • 토큰 중간에 공백이나 한글 등 다른 글자가 섞이면 「토큰 형식이 올바르지 않습니다. 공백·한글 없이 토큰만 붙여 넣으세요.」라는 메시지가 나옵니다(앞뒤 공백은 저절로 지웁니다). 토큰만 다시 붙여 넣으세요.

2-3. 만료와 갱신

  • 토큰은 만들 때 고른 기간(권장 90일)이 지나면 만료됩니다.
  • 만료된 토큰으로 열면 「토큰이 올바르지 않거나 만료되었습니다. ⚙ 설정에서 새 토큰을 저장하세요.」라는 메시지가 나옵니다.
  • 2-1과 같은 방법으로 새 토큰을 만들고, 2-2처럼 저장합니다. 예전 토큰 위에 덮어써집니다.
  • 만료된 토큰은 GitHub 토큰 목록에서 지워도 됩니다.

2-4. 기기마다 한 번씩

  • 토큰은 브라우저마다 따로 저장됩니다. PC·휴대폰·태블릿마다 한 번씩 넣어야 합니다.
  • 기기마다 토큰을 따로 만들기를 권합니다(예: my-todo 휴대폰). 기기 하나를 잃어버려도 그 토큰만 지우면 됩니다.
  • 휴대폰용 토큰은 휴대폰에서 바로 만듭니다: 휴대폰 브라우저에서 홈페이지 ⚙ 설정 → 토큰 발급 페이지 열기를 눌러(GitHub에 LEEYONGJAE-1 계정으로 로그인) 2-1과 같은 설정으로 새 토큰을 만들고, 그 자리에서 복사해 홈페이지 GitHub 토큰 칸에 붙여 넣습니다(2-2). PC에서 만든 토큰을 메신저·메일로 보내 옮기지 마세요(2-5).
  • 공용 PC에서는 쓰고 나서 ⚙ 설정 → 삭제를 누릅니다. 이것은 그 브라우저에서만 지우는 것이고, 토큰 자체는 GitHub에 남습니다.

2-5. 토큰을 잃어버렸거나 남에게 보였다면

  1. GitHub → 프로필 사진 → Settings → Developer settings → Personal access tokens → Fine-grained tokens로 갑니다.
  2. 그 토큰 오른쪽의 Delete를 눌러 지웁니다. 지운 토큰은 더 이상 쓸 수 없습니다.
  3. 2-1부터 새 토큰을 만들어 필요한 기기에 다시 넣습니다.

토큰은 남에게 주지 마세요

  • 토큰이 있으면 누구나 할 일 전체를 읽고 고칠 수 있습니다. 메신저·메일로 보내지 마세요.
  • 이 계정(leeyongjae-1.github.io 주소)으로 다른 GitHub Pages 사이트를 올리면, 그 사이트의 코드가 이 브라우저에 저장된 토큰을 읽을 수 있습니다. 그래서 토큰은 my-todo의 Issues 권한만 주고, 만료 기간을 정해(권장 90일) 만듭니다.

3. 휴대폰·PC에 앱으로 설치

설치하면 주소창 없는 창으로 열리고, 홈 화면·바탕화면에 What's Next 아이콘(달력에 연필로 적는 모양)이 생깁니다. 설치하지 않고 브라우저로 열어도 똑같이 쓸 수 있습니다.

기기·브라우저설치 방법 (홈페이지를 연 상태에서)
안드로이드 크롬오른쪽 위 ⋮ → 앱 설치 (또는 홈 화면에 추가)
아이폰 사파리공유 버튼(□↑) → 홈 화면에 추가
PC 크롬주소창 오른쪽의 설치 아이콘 → 설치 (또는 ⋮ → 전송, 저장, 공유 → 페이지를 앱으로 설치…)
PC 엣지주소창의 설치 아이콘(보일 때) 또는 ⋯ → 앱 → 이 사이트를 앱으로 설치
  • 메뉴 이름은 브라우저 버전에 따라 조금 다를 수 있습니다.
  • 기기마다 토큰을 한 번씩 넣어야 합니다(2-4).

6. 우선순위와 그룹 기준

6-1. 한눈에 보기

이것만 기억하세요

  • 우선순위는 3단계입니다: p1(오늘/긴급) · p2(이번 주, 기본값) · p3(언젠가).

6-4. 그룹은 이렇게 정해집니다

위에서부터 차례로 확인해서 처음 맞는 그룹 하나에 넣습니다.

  1. ⏳ 대기 중: waiting(대기) 라벨이 있으면 여기입니다. 대기 중인 할 일은 마감이 오늘·내일이어도 ⏳ 대기 중에만 보입니다. 단, 마감이 이미 지났으면 🔴 지연에도 대기 배지를 달고 한 번 더 보입니다.
  2. 🔴 지연: 마감일이 오늘보다 앞(이미 지남)이면 여기입니다. 우선순위와 상관없습니다.
  3. 🟠 긴급: p1이거나, 마감이 오늘 또는 내일이면 여기입니다.
  4. 🟡 이번 주: p2이거나, 마감이 7일 안(2~7일 남음)이면 여기입니다.
  5. 🟢 나중에: 위 어디에도 맞지 않는 것, 즉 p3이면서 마감이 없거나 8일 이상 남은 할 일입니다.

헷갈리기 쉬운 점

  • p2는 마감이 아무리 멀어도 🟡 이번 주에 보입니다. 예: 12/20까지 연간계획 작성하기는 🟡입니다. 🟢 나중에로 보내려면 나중에·언젠가를 넣거나 ✏ 변경에서 p3로 바꾸세요.
  • p3라도 마감이 다가오면 저절로 올라옵니다. 나중에 12/20까지 연간계획 작성하기는 지금 🟢 나중에입니다. 12/13부터 🟡 이번 주(7일 이내), 12/19부터 🟠 긴급(내일 마감), 12/21부터 🔴 지연이 됩니다.
  • 🔴 지연은 고르는 말이 없습니다. 마감일이 지나면 저절로 옮겨집니다. 다만 이미 지난 날짜를 적으면(5-3) 경고와 함께 처음부터 🔴 지연에 들어갑니다.
  • 화면은 1분마다 날짜를 확인해서, 자정이 지나면 그룹을 다시 나눕니다.
  • 한 할 일은 한 그룹에만 보입니다(대기 중이면서 마감이 지난 경우만 예외). 그룹 안에서는 마감이 빠른 순이고, 마감 없는 것은 뒤에 옵니다. 마감이 같으면 p1 → p2 → p3, 그다음 번호 순입니다.

6-6. 등록한 뒤 우선순위·마감 바꾸기 (✏ 변경)

  1. 목록에서 그 할 일의 ✏ 변경을 누릅니다(⏳ 대기 전환 바로 다음 버튼). 그 할 일 바로 아래에 변경 칸이 열리고, 버튼 글자가 ✏ 닫기로 바뀝니다.
  2. 우선순위: p1 긴급 · p2 이번 주 · p3 나중에 중 하나를 고릅니다. 지금 값이 미리 선택되어 있습니다(우선순위 라벨이 없던 할 일은 p2). GitHub에서 우선순위 라벨을 두 개 붙였거나 하나도 없는 할 일은, 우선순위를 그대로 두고 저장해도 고른 값 하나만 남깁니다(예: 「#12 우선순위를 p2(이번 주)로 바꿨습니다」).
  3. 마감: 날짜 칸에 지금 마감이 들어 있습니다. 날짜 칸을 눌러 다른 날짜를 고릅니다. 마감을 없애려면 마감 없음을 체크합니다. 체크하면 날짜 칸이 비워지고 잠깁니다. 체크를 풀면 체크하기 전에 날짜 칸에 있던 날짜(없었으면 원래 마감)가 다시 들어갑니다. 마감이 없던 할 일은 마감 없음이 체크된 채로 열립니다. 마감을 넣으려면 체크를 풀고 날짜를 고릅니다.
  4. 저장을 누릅니다. 저장하는 동안은 버튼 글자가 저장 중…으로 바뀌고 칸 전체가 잠겨서 두 번 눌리지 않습니다. 그만두려면 취소나 ✏ 닫기를 누르거나 Esc 키를 누릅니다. 이때는 GitHub에 아무 요청도 가지 않습니다.
  5. 저장이 끝나면 변경 칸이 닫히고, 그 할 일이 맞는 그룹으로 바로 옮겨집니다(목록 전체를 다시 받지 않습니다). 옮겨 간 그룹이 접혀 있었으면 펼쳐 줍니다. 결과는 위쪽 메시지 영역에 나옵니다(아래 표).

다른 기기나 GitHub에서 이미 완료함「#12 이미 완료된 할 일입니다」, 다음 줄에 「목록을 GitHub의 최신 상태로 고쳤습니다. 다른 항목도 바뀌었을 수 있으니 [목록 새로고침]을 누르세요.」아무것도 바뀌지 않았습니다. 그 할 일은 열린 목록에서 빠지고 변경 칸이 닫힙니다. 메시지의 목록 새로고침을 누르세요.
GitHub에서 반복 원본(recurring) 등으로 바뀌어 더 이상 할 일이 아님「#12 할 일이 아니라 바꿀 수 없습니다」, 다음 줄은 위와 같은 안내위와 같습니다.
토큰 만료(401)「토큰이 올바르지 않거나 만료되었습니다. ⚙ 설정에서 새 토큰을 저장하세요.」메시지의 ⚙ 설정 열기를 눌러 새 토큰을 저장합니다(2-3). 새 토큰을 저장하면 목록을 처음부터 다시 불러오고 변경 칸은 닫히므로, ✏ 변경을 다시 눌러 고릅니다.
인터넷 끊김·GitHub 서버 오류「네트워크 오류: 인터넷 연결을 확인한 뒤 다시 시도하세요.」, 「GitHub 서버 오류(500)입니다. 잠시 후 다시 시도하세요.」 등변경 칸과 고른 값은 그대로 남습니다. 잠시 뒤 다시 저장을 누릅니다.
  • ✏ 변경은 그룹 목록의 열린 할 일(⏳ 대기 중 포함)에만 있습니다. "이번 주 완료한 일"과 "반복 할 일 목록"에는 없습니다.
  • 대기 중이면서 마감이 지난 할 일은 🔴 지연과 ⏳ 대기 중 두 곳에 보입니다. 변경 칸은 ✏ 변경을 누른 쪽 아래에 하나만 열립니다.
  • 바뀌는 것은 두 가지뿐입니다. 우선순위를 바꾸면 p1·p2·p3 라벨을 모두 떼고 고른 하나만 붙입니다(다른 라벨은 그대로). 마감을 바꾸면 본문의 Due: 줄만 고칩니다(없으면 넣고, 마감 없음이면 그 줄을 지웁니다). 제목과 본문의 다른 줄(완료 기준·메모·다음: 줄 괄호 속 Due·하위 작업)은 그대로입니다.
  • 저장할 때 먼저 GitHub의 최신 상태를 확인하고, 변경 칸을 연 뒤 손댄 칸만 보냅니다. 그래서 그 사이 다른 기기에서 바꾼 다른 값을 덮어쓰지 않습니다. 다른 곳에서 이미 같은 값으로 바꿔 놓았으면 「#12 바뀐 내용이 없습니다」와 「다른 곳에서 이미 같은 값으로 바뀌어 있어 목록만 최신으로 고쳤습니다.」가 나옵니다.
  • 키보드로도 쓸 수 있습니다. 칸이 열리면 선택된 우선순위에 포커스가 가고, 방향키로 우선순위를 고르고 Tab으로 마감 칸과 저장·취소 버튼으로 옮겨 갑니다. 저장하거나 취소·Esc로 닫으면 포커스가 그 할 일의 ✏ 변경으로 돌아옵니다.

예비 방법: GitHub에서 직접 고치기

홈페이지에서 바꿀 수 없을 때나 제목을 고치고 싶을 때 씁니다.

  1. 할 일의 #번호를 누르면 GitHub 이슈가 열립니다.
  2. 우선순위: 이슈의 Labels에서 p1·p2·p3 중 하나만 남깁니다. 두 개가 함께 붙어 있으면 홈페이지는 p1 → p2 → p3 순으로 앞의 것을 씁니다. 우선순위 라벨이 하나도 없으면 p2로 봅니다.
  3. 마감: 이슈 본문을 편집해 Due: 2026-10-20 줄을 고치거나 지웁니다. 날짜는 꼭 YYYY-MM-DD 형식으로 씁니다.
  4. 제목: 이슈 제목 옆 Edit로 고칩니다. 홈페이지에는 제목을 바꾸는 기능이 없습니다.
  5. 홈페이지에서 새로고침을 누릅니다. 1분쯤 늦게 반영될 수 있습니다.

7. 완료하기 · 되돌리기

7-1. 버튼으로 완료

그 할 일의 완료를 누릅니다. 하위 작업이 남아 있으면 먼저 「하위 작업 2개가 남았습니다. 완료할까요?」라고 묻습니다. 완료 또는 취소를 누릅니다.

7-2. 문장으로 완료

입력무엇을 완료하나
#3 끝#3 할 일
12번 done#12 할 일
견적서 송부 완료제목에 "견적서 송부"가 든 할 일
견적서 끝났어제목에 "견적서"가 든 할 일
보고서 제출했음제목에 "보고서 제출"이 든 할 일

번호가 없으면 제목으로 찾습니다.

  • 적은 낱말(두 글자 이상)이 모두 제목에 들어 있는 열린 할 일이 딱 하나면 바로 완료합니다.
  • 하나로 정해지지 않으면(비슷한 할 일이 여러 개이거나, 일부 낱말만 맞으면) 「어떤 할 일을 완료할까요?」라는 질문과 함께 후보 버튼(최대 8개)이 나옵니다. 하나를 누르거나 취소를 누릅니다.
  • 하나도 없으면 「일치하는 할 일이 없습니다」라는 메시지가 나옵니다.
  • 예: 열린 할 일이 #3 "견적서 송부", #7 "견적서 검토"라고 합시다. 견적서 송부 완료는 #3을 바로 완료합니다. 견적서 완료는 #3·#7 중에서 고르게 합니다.
  • 등록할 때 제목에서 빠진 우선순위 말(빨리·급한·긴급·나중에 등, 6-2)은 완료 문장에 다시 적어도 됩니다. 예: 보고서 빨리 작성하기로 등록한 "보고서 작성"은 보고서 빨리 작성 완료로도 바로 완료합니다.
  • 반복 할 일의 원본 번호나 아침 브리핑 번호를 적으면 완료하지 않고 안내만 합니다.

7-3. 완료하면 일어나는 일

  1. 먼저 GitHub의 최신 상태를 확인합니다. 다른 기기에서 이미 완료했으면 「이미 완료된 할 일입니다(다른 곳에서 처리됨). 목록을 새로고침하세요.」라는 메시지가 나오고, 아무것도 바꾸지 않습니다.
  2. 이슈에 「완료: 홈페이지에서 처리」 댓글을 달고 이슈를 닫습니다.
  3. 「완료했습니다: #3 견적서 송부」라는 메시지와 함께 되돌리기 (5초) 버튼이 나옵니다.

7-4. 되돌리기 (5초)

  • 버튼의 숫자가 5초부터 줄어듭니다. 그 안에 누르면 이슈를 다시 열고, 완료 댓글을 지우고, 자동으로 등록된 다음 단계와 회신 확인도 닫습니다.
  • 결과: 「되돌렸습니다: #3 견적서 송부 — 다시 열린 할 일입니다.」
  • 5초가 지나면 버튼이 사라집니다. 그 뒤에는 GitHub에서 그 이슈를 열어 다시 열기(Reopen)를 누릅니다.

7-5. 다음 단계 자동 등록

  • 본문에 다음:이 있는 할 일(5-2의 →)을 완료하면, 묻지 않고 다음 할 일을 새로 등록합니다: 「다음 단계 등록: #22 회신 확인」
  • 영역은 둘 중 하나라도 개인이면 개인입니다. 프로젝트는 원래 할 일의 것을 이어받습니다. 제출 대상은 다음 단계에 따로 적지 않았으면 원래 할 일에서 이어받습니다.
  • 우선순위는 다음 단계 문장의 말(긴급·빨리 등)을 따르고, 없으면 p2입니다.
  • 마감은 처음 입력한 날 기준으로 고정됩니다. 예: 10/15에 "→ 금요일까지 회신 확인"이라고 적었다면 언제 완료하든 마감은 2026-10-16입니다. 그 날짜가 지났어도 그대로 등록합니다.
  • 한 단계만 이어집니다. 새로 생긴 할 일에는 다음:이 없습니다. 메모에는 이전 단계: #번호가 남습니다.

7-6. "회신 확인도 등록할까요?"

  • 다음:이 없고, 제목에 송부·발송·제출·요청·전달·문의가 든 할 일을 완료하면 회신 확인도 등록할까요? (3일 뒤 마감, 대기 중) 버튼이 나옵니다.
  • 누르면 <원래 제목> 회신 확인을 마감 3일 뒤, ⏳ 대기 중, p2로 등록합니다. 영역·프로젝트·제출 대상은 이어받습니다. 예: 「회신 확인을 등록했습니다: #23 견적서 송부 회신 확인」, 「마감 10/18(일) · D-3 · 대기 중」
  • 제목에 이미 "회신 확인"이 있으면 나오지 않습니다(끝없이 이어지지 않게).
  • 5초가 아직 안 지났으면 되돌리기가 남아 있습니다. 누르면 방금 등록한 회신 확인도 함께 닫습니다.

9. 🆘 막막해요

손이 안 가는 할 일을 Claude(AI)에게 맡겨 진단하고 잘게 나누는 기능입니다. Claude는 그 이슈에 답글(댓글)로 진단 → 완료 기준 제안 → 하위 작업(체크리스트 3~7개) → 첫 행동을 적습니다. Claude는 이슈 본문과 라벨을 바꾸지 않습니다. 본문에 넣는 일은 홈페이지의 본문에 반영 (5개) 버튼이 합니다.

9-1. 순서

  1. 할 일의 🆘 막막해요를 누릅니다. 내 토큰으로 그 이슈에 요청 댓글이 달리고 「#8 🆘 막막해요 요청을 보냈습니다.」라는 메시지가 나옵니다. 버튼은 🆘 요청됨으로 바뀝니다.
  2. 1~3분 기다립니다. GitHub에서 Claude가 실행되어 답글을 씁니다.
  3. 페이지를 열어 두면 홈페이지가 30초마다, 최대 6분 동안 답글을 확인합니다. 답이 오면 메시지 영역에 「🆘 #8 에 답변이 도착했습니다」라는 알림과 답변 보기 · 본문에 반영 (5개) 버튼이 나옵니다.
  4. 6분 안에 오지 않으면 「🆘 #8 아직 답변이 없습니다. 잠시 뒤 항목의 [💬 답변 보기]로 확인하세요.」라는 메시지가 나옵니다. 페이지를 닫거나 새로 열면 자동 확인은 멈춥니다. 그때는 나중에 💬 답변 보기를 누르면 됩니다.
  5. 💬 답변 보기를 누르면 그 할 일 아래에 "답변" 칸이 열립니다.
  6. 하위 작업이 마음에 들면 본문에 반영 (5개)를 누릅니다.

  • ✏ 변경은 그룹 목록(🔴 지연 · 🟠 긴급 · 🟡 이번 주 · 🟢 나중에 · ⏳ 대기 중)의 열린 할 일에만 있습니다. "이번 주 완료한 일"과 "반복 할 일 목록"에는 없습니다.
  • 휴대폰처럼 좁은 화면에서는 카드 아래쪽 버튼 줄에 있습니다(⏳ 대기 전환 다음).
  • 반복 할 일의 규칙(원본)은 GitHub에서 원본 본문의 반복: 줄을 고칩니다(10-4).
"토큰이 올바르지 않거나 만료되었습니다" (401)

「토큰이 올바르지 않거나 만료되었습니다. ⚙ 설정에서 새 토큰을 저장하세요.」

  • 만들 때 고른 기간(권장 90일)이 지나 만료됐거나, GitHub에서 토큰을 지웠거나, 붙여 넣을 때 일부가 빠진 경우입니다.
  • 메시지의 ⚙ 설정 열기를 누르고 새 토큰을 저장하세요(2-3).
"권한이 없습니다" (403)

「권한이 없습니다. 토큰에 my-todo 저장소의 Issues 읽기·쓰기(Read and write) 권한이 있는지 확인하세요.」

  • 토큰에 Issues: Read and write가 빠졌을 때 나옵니다. Administration 등 다른 권한을 대신 고른 경우도 같습니다(2-1의 주의 상자).
  • Issues를 Read-only로 만들었다면 목록은 보여도 등록·완료할 때 이 메시지가 나옵니다.
  • 토큰을 새로 만들어(Issues: Read and write) 다시 저장하세요.
  • 잠깐 사이에 요청이 너무 많으면 「GitHub API 사용량 제한에 걸렸습니다. 잠시 후 다시 시도하세요.」라는 메시지가 나옵니다. 이것은 권한 문제가 아니니 잠시 기다리세요.
"저장소를 찾을 수 없거나 접근 권한이 없습니다" (404)

「저장소를 찾을 수 없거나 접근 권한이 없습니다. 토큰을 만들 때 my-todo 저장소를 선택했는지 확인하세요.」

토큰을 만들 때 Repository access에서 my-todo를 고르지 않았거나, 다른 계정(Resource owner)으로 만든 경우입니다. 2-1대로 다시 만드세요.

연결 테스트는 성공하는데 목록이 안 보여요

연결 테스트는 저장소의 기본 정보만 읽어 봅니다. 이 정보는 Metadata 권한만으로도 읽혀서, Issues 권한이 없어도 성공합니다. 목록 자리에 「목록을 불러오지 못했습니다: 권한이 없습니다. …」라는 메시지가 보이면 Issues 권한이 빠진 것입니다. Issues: Read and write로 토큰을 새로 만드세요.

새 휴대폰(또는 새 브라우저)에서 쓰려면?

홈페이지를 열고 토큰을 한 번 넣으면 됩니다. 그 기기용 토큰을 새로 만들기를 권합니다(2-4). 앱으로 설치하려면 3장을 보세요.

할 일 데이터는 어디에 있나요? 백업은?
  • 모든 할 일은 GitHub 비공개 저장소 my-todo의 이슈로 저장됩니다. 홈페이지나 브라우저에는 토큰과 몇 가지 화면 설정(고른 프로젝트 등)만 남습니다.
  • 브라우저 기록을 지우거나 토큰을 삭제해도 할 일은 지워지지 않습니다. 완료한 할 일도 닫힌 이슈로 남습니다.
금액·계약 조건·개인정보를 적어도 되나요?

적지 마세요. 할 일 내용은 GitHub에 저장되고, 🆘를 쓰면 Claude(Anthropic)로도 전송됩니다. 대신 "자료 위치"(예: 공유 드라이브 폴더 이름)만 적으세요.

제목이나 댓글에 '@claude'를 써도 되나요?
  • GitHub에서 @claude가 든 댓글이나 새 이슈를 쓰면 GitHub의 Claude가 실행됩니다(사용량이 듭니다).
  • 홈페이지에 입력한 문장 속 @claude는 저절로 @ claude로 바뀌어 저장되므로 실행되지 않습니다.
  • GitHub 앱·웹에서 직접 쓸 때는 Claude를 부르려는 게 아니라면 @claude를 쓰지 마세요.
다크 모드는 어떻게 켜나요?

따로 버튼은 없습니다. 휴대폰·PC의 화면 모드(밝게/어둡게) 설정을 그대로 따라갑니다.

인터넷이 끊기면요?
  • 할 일은 GitHub에 있어서 인터넷이 있어야 보고 고칠 수 있습니다. 오프라인 모드는 없습니다.
  • 연결이 안 되면 「네트워크 오류: 인터넷 연결을 확인한 뒤 다시 시도하세요.」라는 메시지가 나옵니다. 30초 넘게 응답이 없으면 「응답이 너무 늦어 요청을 중단했습니다. 네트워크를 확인한 뒤 다시 시도하세요.」라는 메시지가 나옵니다.
  • 목록을 못 받으면 「목록을 불러오지 못했습니다: …」라는 메시지와 다시 시도 버튼이 나옵니다. 연결이 돌아오면 누르세요.
"이 탭을 닫으면 사라집니다"라고 나와요

「저장된 토큰: 있음 (브라우저 저장소를 쓸 수 없어 이 탭을 닫으면 사라집니다)」는 시크릿 창처럼 브라우저 저장소를 쓸 수 없는 상태라는 뜻입니다. 보통 창에서 열면 토큰이 저장됩니다.

GitHub 앱에서 이슈를 닫았더니 다음 단계가 안 생겼어요

다음 단계 자동 등록과 회신 확인 제안은 홈페이지에서 완료할 때만 일어납니다(7-5). GitHub에서 다시 열고(Reopen) 홈페이지에서 완료하거나, 다음 할 일을 직접 등록하세요.

공용 PC에서 썼어요

⚙ 설정 → 삭제를 누르면 「이 브라우저에서 토큰을 삭제했습니다. 토큰 자체를 폐기하려면 GitHub → Settings → Developer settings → Personal access tokens에서 삭제하세요.」라는 메시지가 나옵니다. 불안하면 GitHub에서 그 토큰도 지우세요(2-5).
